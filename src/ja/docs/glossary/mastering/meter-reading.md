# マスタリングメーターの読み方

マスタリングメーターは、まとめて読んで初めて役に立ちます。

ブラウザデモでは、ラウドネス、ピークレベル、クレストファクター、相関値（コリレーション）、フェーズスコープ、ステレオイメージを表示します。それぞれ、音量、ピーク安全性、密度、ステレオの再生互換性を別の角度から見たものです。

::: tip メーターはグループで読み、最後は耳で判断する
単独の数値でマスターの良し悪しは決まりません。ラウドネス＋ピークで「ターゲットに合っていて安全か」を、クレストファクター＋相関値で「生命感が残りモノラルでも崩れないか」を確かめます。メーターは問題の*発見*に使い、確認は耳で行ってください。
:::

## 主要な読み方

ラウドネスの単位は [LUFS](../lufs.md)（Loudness Units relative to Full Scale）で、サンプル値そのものではなく体感ラウドネスを表します。

| メーター | 確認できること |
|---------|-----------|
| Output LUFS | 選んだ配信ターゲットに近いか。 |
| ピーク／True Peak | 再生や変換に対するピーク安全性があるか。 |
| クレストファクター | ピークと平均の動きが残っているか。 |
| 相関値（コリレーション） | モノラル再生に耐えるステレオイメージか。 |
| フェーズスコープ | ステレオフィールドが安定しているか。 |
| ステレオイメージ | 効果的なサイドエネルギーか、危険な広げ方か。 |

下のデモが実際のクリップで確認できるのは、表の最初の 2 行、ラウドネスとピーク安全性です。相関値とフェーズスコープは別の測定で、[モノラル互換性](../concepts/mono-compatibility.md)のデモで扱います。

## ラウドネスとピークの読みの詳細

「ラウドネス」と「ピーク」には、それぞれいくつかの種類があり、メーターは別々に表示します。ラウドネスの読みは ITU-R BS.1770 と EBU R128 に、ラウドネスレンジは EBU Tech 3342 に従います。

| 読み | 測り方 | わかること |
|------|--------|------------|
| モーメンタリーラウドネス | 400 ms の窓、100 ms ごとに更新 | その瞬間のレベル。打点ごとに跳ねる |
| ショートタームラウドネス | 3 秒の窓 | フレーズ単位のレベル。再生しながら見るのはこれ |
| インテグレーテッドラウドネス | 曲全体を 400 ms のブロックに分け、−70 LUFS 未満のブロックを除き、残りの平均より 10 LU 以上低いブロックも除いて求める | 配信ターゲットが指す、ひとつの数値 |
| ラウドネスレンジ（LRA） | 曲全体のショートタームの読みのうち、平均より 20 LU 以上低いものを除き、10 パーセンタイルと 95 パーセンタイルの差を LU で表す | 静かな部分と大きい部分のあいだで、ラウドネスがどれだけ動くか |
| サンプルピーク | 保存されたサンプル値の最大、dBFS | サンプルのあいだにあるピークを見逃すことがある |
| True Peak | 4 倍オーバーサンプリングで再構成した波形のピーク、dBTP | サンプルピークを下回ることはない。納品時のシーリングはこれで決める |
| PLR（ピーク対ラウドネス比） | True Peak からインテグレーテッドラウドネスを引いた値、dB | 小さいほど密度が高く強くリミットされ、大きいほど開放的でダイナミック |

サンプルピークと True Peak の差は、波形で見るとわかりやすくなります。

## 最初に見るもの

まずラウドネスとピーク安全性を確認します。ターゲットから大きく外れているか、クリップしているマスターは、まだ完成していません。

次にクレストファクターと相関値を見ます。ターゲットに合っていても、クレストファクターが低すぎると生命感のない音に聞こえます。ヘッドホンで広く聞こえても、相関値がマイナスに振れるならモノラル再生で崩れやすくなります。

## 完璧な数値を追わない

ジャンルによって妥当な値は変わります。密度の高い EDM、スカスカなアコースティック、スピーチ、AI 生成音源が同じクレストファクターやステレオ値になる必要はありません。「業界標準の値」をひとつだけ目標にすると、素材によっては不自然な処理を続けてしまうので、まずは曲調と公開先に合った妥当なレンジを見極めるところから始めます。

判断の手順は次のとおりです。

1. ラウドネスマッチングを有効にして Before／After を比較する。
2. パンチの喪失、ハーシュさ、ポンピング感、ステレオの偏りを聴く。
3. リファレンストラックと同じレンジに入っているかをチェックする。数値を完全一致させる必要はない。
4. 別環境（スマートフォン、安いイヤホン、車載スピーカー）でも違和感がないかを確認する。

:::: details 実装メモ

デモには、2 つの計測経路があります。

| 経路 | 目的 | 表示／保存先 |
|------|------|--------------|
| 軽量な UI 用メトリクス | 操作中の即時フィードバック | Vue コンポーネント |
| 正式なレンダリング結果メトリクス | レポートに残す処理結果 | libsonare の render 結果と JSON レポート |

UI のピークは、ソースまたはレンダリング後のバッファを全サンプル走査して求めています。ピークは安全性の指標であり、間引いて読むと 1 サンプルだけのクリップを飛ばしてしまうためです。RMS・クレストファクター・相関値は平均量なので、応答性を保つために約 20 万点へストライドサンプリング（一定間隔で間引いて読む）したサブセットから計算しています。フェーズスコープとステレオイメージは可視化補助です。

そのため、UI に表示される数値と JSON レポート内の値が少し違って見えることがあります。処理結果として記録する値は JSON レポート側を基準にしてください。
