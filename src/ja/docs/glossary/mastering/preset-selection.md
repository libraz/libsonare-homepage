# マスタリングプリセットの選び方

プリセットはあくまで出発点です。ソースに合いそうなチェーン形状を選ぶものではあっても、ユーザー以上に楽曲の意図を理解しているわけではありません。

素材の密度、トランジェントの性質（ドラムや子音の立ち上がりの鋭さ）、そして公開先に近いプリセットを選び、その後でクイックマスターのマクロや Studio モードで小さく補正していきます。

## プリセット早見表

| プリセット | 向いている素材 | 守りたいもの |
|-----------|----------------|--------------|
| Pop | 一般的な現代ポップス系のミックス。 | バランスの取れたラウドネス、ボーカルプレゼンス、安定したトーン。 |
| EDM / Dance | 密度の高いエレクトロニック楽曲。 | コントロールされたピーク、タイトなリリース、強い最終レベル。 |
| Acoustic | スカスカな／自然なレコーディング。 | トランジェント、息遣い、控えめなコンプレッション。 |
| Hip-Hop / R&B | ビート主導の楽曲とフォーカスされたボーカル。 | 低域の重みとボーカルセンター。 |
| AI-Generated | Suno／Udio などの生成音源、AI 由来のアーティファクト。 | ディノイズ、上側帯域の補完、過剰にならない仕上げ。 |
| Speech / Podcast | 朗読・ナレーション・スピーチ中心の素材。 | 声の明瞭さ、控えめなステレオ幅、安定したラウドネス。 |

## 選び方

2 つのプリセットがほぼ同じに聞こえるなら、副作用の少ない方を選びます。大きく派手に聞こえるプリセットは、数秒では印象的でも、長く聴くと疲れることがあります。

実用的な流れ:

1. 明確に別ジャンルだと言える場合を除き、まず Pop から始める。
2. ソースにもっとも近い専用プリセットを試す。
3. レンダリングし、ラウドネスマッチングで比較する。
4. 専用プリセットが過剰処理に感じたら、Pop か Acoustic に戻す。
5. 「何のために動かすか」を言葉で説明できるコントロールだけ、Studio モードで触る。

## AI 生成音源

AI 生成音源には、弱い上側倍音・ヒスノイズ・にじんだトランジェント・光沢のあるリバーブ的な残り、といった特徴が混じっていることがあります。AI-Generated プリセットがリペアと Air バンド復元寄りなのは、このためです。エンジン側の `aiMusic` はジャンル系プリセットの中では数少ないリペアステージを持つもので、トーン処理に入る前に `declick`・`denoise`・`dereverb` を走らせます。

ただし「生成音源だから常に AI プリセット」というわけではありません。ソースがすでに明るすぎたり脆い倍音を持っていたりする場合は、もっとシンプルなプリセットのほうが合うこともあります。

::: warning AI-Generated プリセットを反射的に使わない
このプリセットのリペアと Air バンド復元は、くぐもった／ヒスの多い／アーティファクトを含むソースを前提にしています。すでに明るい・脆い素材では過剰処理になります — Pop のようなシンプルなプリセットのほうが安全です。
:::

## 修復プリセット: リペアだけを行うもの

エンジンのプリセットのうち 5 つは、他とは性格が違います。`vinyl`・`tapeHiss`・`fieldRecording`・`voiceMemo`・`shellac78` はリペアステージだけを有効にし、レベルには触れません。ラウドネスターゲットも True Peak の上限も、EQ もダイナミクスもありません。「この曲をどう仕上げるか」ではなく「この録音のどこが壊れているか」が問いになったときに選ぶものです。デモのプリセットメニューには含まれず、CLI の `--preset`、各バインディング、チェーン設定から名前で指定します。

ステージそのものと順序、パラメータは[リペアと入力コントロール](./repair.md)と[マスタリングプロセッサ](../../mastering-processors.md)で扱います。ここではどのプリセットを選ぶかだけを見ます。

| プリセット | 想定する損傷 | 有効にするステージ |
|-----------|-------------|-------------------|
| `vinyl` | LP の取り込み。溝の傷によるクリックとポップ、表面のクラックル、全体の下に敷かれたノイズフロア。 | `declick`・`decrackle`・`denoise` を、すべて既定値のまま。 |
| `shellac78` | 78 回転盤の取り込み。より幅の広いポップ、より密なクラックル、より高いノイズフロア。 | 同じ 3 つを、それぞれ強めに調整したもの。クリックの許容幅を広げ、クラックルの閾値を敏感にし、ディノイズの深さを 26 dB ではなく 32 dB に。 |
| `tapeHiss` | テープ。広帯域のヒスだけ。 | `denoise` のみ。 |
| `fieldRecording` | 現場録音。周波数がずれる電源ハム、環境ノイズのフロア、そして場所そのものの響き。 | 適応追従つきの `dehum`・`denoise`・`dereverb`。 |
| `voiceMemo` | スマートフォンや PC での録音。端末自身のゲイン制御で起きるクリッピング、高いマイクのノイズフロア、処理されていない部屋。 | `declip`・`denoise`・`dereverb`。 |

### 聴いてから選ぶ

- 音符の合間に入るチリチリしたクリックやポップと、その下に敷かれた一定の表面ノイズ: `vinyl`。ポップが鋭くなく幅広で鈍い音になり、表面ノイズが途切れず連続して聞こえるなら `shellac78` で、同じ 3 ステージをそれぞれ強めにかけます。
- クリックもブーンという音もなく、一定のヒスだけ: `tapeHiss`。ステージが 1 つだけの最小のプリセットなので、不満がヒスだけという素材なら何であれ最初に試す候補になります。
- 無音部でも鳴り続ける低いブーンという音と、距離感や屋外の空気感: `fieldRecording`。この `dehum` は設定上の 50 Hz を決め打ちせず実際の電源基本波を追従するので、どんな電源回路につながっていたか分からない機材の録音にはこれが選択肢になります。
- 大きな声で音が潰れたり割れたりし、ヒスっぽいフロアがあり、狭い部屋の反響がある: `voiceMemo`。修復プリセットの中で `declip` を走らせるのはこれだけで、クリップしたボイスメモを `fieldRecording` に通しても歪みは残ります。

選ぶ前に知っておきたい空白が 2 つあります。`dehum` を走らせるのは `fieldRecording` だけ、`declip` を走らせるのは `voiceMemo` だけです。ハムの乗った LP 取り込みや、クリップしたテープの両方の損傷をまとめて扱うプリセットはありません。

### 5 つのどれにも当てはまらないとき

道は 2 つあり、どちらもプリセットを結論ではなく出発点として扱います。

1. **ファイル自身に決めさせる。** `--preset` を付けない `sonare repair` は 6 つの検出器で計測し、証拠が求めるステージだけを有効にします。`--explain` を付ければ各ステージを選んだ理由が表示されます。クリップした LP 取り込みのような混在ケースにはこちらが向いています。
2. **いちばん近いプリセットから始めて、足りないステージを足す。** どのステージにも `repair.<stage>.enabled` キーがあるので、`--preset vinyl --params repair.dehum.enabled=true` で vinyl にハムノッチを加えられます。`repair` の `--params` が受け付けるのは `repair.` で始まるキーだけです。

修復プリセットはレベルを設定しません。損傷を取り除いたあとは、ジャンル系プリセットで 2 パス目としてマスタリングするか、両方を持つチェーン設定を 1 つ組みます。`aiMusic`・`speech`・`audiobook` は、すでにそうなっているジャンル系プリセットです。

:::: details 実装メモ

プリセットはレンダリング前に、libsonare のマスタリング構成へ変換されます。

プリセットはコンプレッサーのタイミング・レシオ挙動・リペア有効化・Air バンド量・エキサイターのフォーカス・ステレオ幅の上限・リミッターのリリース挙動などを調整します。修復プリセットのステージ構成はエンジン自身のプリセットテーブルから来るので、CLI で `--preset voiceMemo` が走らせる内容と、そのプリセットから組んだチェーン設定が持つ内容は一致します。

クイックマスターの Tone・Width・Dynamics マクロは、これらのプリセット既定値に対するマクロレベルのオフセットとして加算されます。

Studio モードで個別のステージを直接変更した場合は、その状態が JSON レポートにそのまま反映されます。レポートには適用されたプリセット名と、上書きされたパラメータ値の両方が記録されるので、後から再現する際に「どのプリセットを元にして、どこを動かしたか」を追えるようになっています。
