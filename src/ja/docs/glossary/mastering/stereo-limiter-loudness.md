# ステレオ、リミッター、ラウドネスコントロール

マスタリングチェーンの最終段は、マスターの広がり・ピーク安全性・レンダリング後のラウドネスを決めるブロックです。

ここの各コントロールはまとめて判断します。ステレオ幅を広げるとピークの振る舞いが変わることがあり、ラウドネス目標を上げればリミッターは深く働きます。シーリングを下げればコーデック変換には安全になりますが、稼げるラウドネスは減ります。

## ステレオ幅

ステレオ幅はサイド成分のエネルギーを調整します。広げると大きく感じられることはありますが、モノラル互換性が弱まったり、低域が不安定になったりします。

ラウドネスマッチした A/B と相関値を併用しながら判断してください。スピーチ素材では控えめが基本です。

ステレオ幅を動かすと全体のレベルも動きます。幅の変更に合わせてかかるエネルギー補正は信号に依存しない固定ゲインなので、Mid と Side のエネルギーが等しい素材でしか相殺されません。通常のミックスでは Side は Mid よりはるかに小さいため、レベルは保たれていると考えず、ステレオ幅を動かしたらラウドネスを測り直してください。

戻すべきサインは、モノラルに切り替えたときにボーカル・キック・ベース・スネアの芯が弱くなることです。ステレオでは派手に聞こえても、センターが痩せる設定はマスタリングの改善ではなく単なるバランス移動です。

::: warning ステレオ幅は必ずモノラルで確認する
幅を決める前にモノラルへ折りたたんでください。センターの芯が痩せるなら幅が広すぎます。リミッターは最後の安全装置であって、密度を作る道具ではありません。常に深く働いているなら、シーリングを上げる前に、前段の低域・コンプレッサー・インプットゲインを直します。
:::

## True Peak リミッター

True Peak リミッターは、サンプル間を再構成した後や、コーデック変換後に出てくるピークを捕まえます。リミッターのシーリングは最終的な安全限界で、ストリーミング系の納品では `-1 dBTP` 前後がよく使われます。dBTP は decibels true peak の略で、サンプル点そのものではなくサンプル間まで含めて測ったピークを指します。

リミッターが常に深く働いている場合は、シーリングだけを緩める前に、前段の低域バランス・コンプレッサー・インプットゲインを見直します。リミッターは最後の安全装置であり、ミックス全体の密度を作る主役ではありません。

## ルックアヘッドと True Peak 安全性

ルックアヘッドは、速いピークが出力に到達する前にリミッターが先読みするための時間です。オフラインレンダリングでは数 ms 程度で十分なことが多いです。短すぎると鋭いピークが歪み、長すぎるとレイテンシが増えてアタック感が柔らかくなります。

## ラウドネス目標

ラウドネス目標は、レンダリング後ファイルの Integrated [LUFS](../lufs.md)（Loudness Units relative to Full Scale）の目標値です。Integrated は曲全体にわたる*ゲート付き*の平均で、無音や極端に静かな部分は平均に入る前に除外されます。デモでは `-14 LUFS`、`-16 LUFS` といった公開先を想定した値と、任意のカスタム値が選べます。

ラウドネスステージは、ピークがシーリングに触れた時点で止まるゲイントリムではありません。ステージ入力を計測し、`target − current` の固定ゲインを算出して適用したうえで、シーリングに合わせた True Peak リミッターを通します。仕上がったミックスの大半はピークノーマライズ済みで、シーリングまでの余裕はほぼ 0 dB です。その余裕の範囲内でしかゲインを動かさないステージでは、目標がどれだけ離れていてもラウドネスは一切動きません。目標に到達させているのはリミッターです。固定ゲインはシーリングを超える方向に信号を押し上げることを許され、リミッターがそれをシーリングの下へ戻します。

`maxLimiterGainReductionDb` は、この押し上げ幅の上限です。単位は dB の深さで、既定値は `12`、有限かつ 0 以上でなければなりません。固定ゲインがシーリングまでのピーク余裕を超えられるのは最大でこの値までなので、ステージが目標に向かう途中でリミッターに求めるリダクションはおよそ 12 dB を超えません。上限が効くのはあくまで `target − current` までのゲインに対してで、目標より大きなマスターを作ることはできません。この値によって、ピークがどの程度立った入力までステージがノーマライズを試みるかが決まります。`0` にすると厳密な余裕クランプに戻り、ピークノーマライズ済みの入力はどんな目標を与えても入力時のラウドネスのままになります。

上限に達した場合、呼び出し側が受け取るのは目標ではありません。固定ゲインは `余裕 + maxLimiterGainReductionDb` で止まり、シーリングはどの設定でも守られ、レンダリング後ファイルは要求した LUFS より小さく仕上がります。結果にはそのことが明示されます。`loudnessTargetLimited` が true になり、`outputLufs` は実際に到達したラウドネス、`appliedGainDb` はリミッターのリダクションを含まない固定ゲインだけを示します。上限の内側でもステージは反復しません。1 パスでゲインを算出し、リミッターがその一部を削り、その不足分も同じ形で報告されます。ステージのパラメータ一覧は [マスタリングプロセッサ](../../mastering-processors.md) にあります。

## 出力レンダー

ブラウザデモはローカルで処理し、ステレオ 16-bit PCM の WAV と JSON レポートを書き出します。音源はアップロードされません。

:::: details 実装メモ

libsonare のステレオイメージャーは Mid/Side 処理で動作します。ステレオ信号を、両チャンネルに共通する成分（センター）である Mid と、両チャンネルで異なる成分（広がり）である Side に分け、Side のレベルを調整します。これがステレオ幅で操作するサイド成分の仕組みです。デコリレーションはその上に載るオプションとして用意されています。

エネルギー補正を有効にすると、Mid と Side の両方に `sqrt(2 / (1 + width^2))` のゲインがかかります。このゲインは幅の設定値だけから決まり、そのときのサンプル値からは導かれません。処理が線形に保たれ、相互変調成分を生まないのはこのためですが、全体のエネルギーが一定に保たれるのは Mid と Side のパワーが等しいという前提のもとだけです。実際の楽曲素材はその前提を満たさないので、広げれば全体のレベルはわずかに下がり、狭めれば上がります。

True Peak リミッターは、ルックアヘッド・リンクピーク検出・オーバーサンプリングされた True Peak 経路を併用します。ラウドネスステージは入力を計測し、LUFS 目標に到達するためのゲインを計算したうえで、そのゲインをシーリングまでの余裕に `maxLimiterGainReductionDb` を足した値で制限します。その後に通す True Peak リミッターは、単体の `maximizer.loudnessOptimize` プロセッサとチェーン内の `loudness` ステージが共有する 1 つの設定から組み立てられるため、どのラウドネス経路でもリミッティングは同じです。リミッター自身のリダクションは `loudness.optimize` ステージのゲインリダクションとして、`appliedGainDb` とは別に報告されます。

デモでは 4 倍オーバーサンプリングを既定にしています。実行されたステージ名は JSON レポートにも出力されるため、最終チェーンの監査に利用できます。シーリングと LUFS 目標がぶつかった場合は、ピーク安全性が優先される設計です。「LUFS は届いていないが True Peak には到達した」という状態は、レポートの applied gain と output LUFS から判定でき、チェーンの結果では `loudnessTargetLimited` として直接フラグが立ちます。

::::
