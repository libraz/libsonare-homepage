# タイムストレッチとピッチシフト

テープを速く回すと、ピッチ*と*長さが一緒に変わります。現代の編集 DSP は、この 2 つを分離します。

| 操作 | 変えるもの | 保ちたいもの |
|------|------------|--------------|
| **タイムストレッチ** | 長さ | ピッチ |
| **ピッチシフト** | ピッチ | 長さ |

このページでは、その分離の仕組みを説明し、libsonare のストレッチバックエンドがそれをどう実装しているかを示します。用語を先に押さえたい場合は [編集の基礎](../concepts/editing-basics.md) を読んでください。

## フェーズボコーダ

中心的な道具は**フェーズボコーダ**です。

大まかには次の 3 段階で動きます。

1. STFT（short-time Fourier transform、短時間フーリエ変換）で音声を短い時間・周波数フレームに分ける。
2. そのフレームを時間軸方向にリサンプリングし、進む速さを変える。
3. 部分音がにじまず続くように位相を作り直す。

手順 1 のフレーム分割は、解析機能が共通して使うものと同じです。フレームの切り出し方は [スペクトログラムと STFT](../analysis/spectrogram-stft.md) に図があるので、位相の話に入る前に見ておくと分かりやすくなります。

難しいのは**位相の整合**です。STFT は各フレームを周波数*ビン*、つまり狭い周波数帯ごとの区画に分けます。フレームの間隔を解析時と変えると、音を構成する個々の周波数成分（*部分音*）が途切れず続くように、各ビンの位相を再伝播させなければなりません。ここを誤ると、金属的で「位相っぽい」アーティファクトになります。

直感的には、音を「短い時間の薄切り」に分け、その薄切りを並べ直す作業です。薄切りを間引けば速く（短く）なり、複製すれば遅く（長く）なります。このとき各切れ目で波がなめらかにつながるよう位相を調整するのが、フェーズボコーダの肝心な仕事です。

## 2 つの操作、1 つのバックエンド

| 操作 | 変えるもの | 保つもの | 方法 |
|------|------------|----------|------|
| タイムストレッチ | 長さ | ピッチ | フェーズボコーダが時間軸をスケール |
| ピッチシフト | ピッチ | 長さ | 比率でタイムストレッチし、元の長さへリサンプル |

ピッチシフトとタイムストレッチがバックエンドを共有するのはこのためです。ピッチシフトは、タイムストレッチの後にリサンプリングしたものです。

`rate > 1.0` はクリップを短くし、`semitones = 12` は 1 オクターブ上へ動かします。

半音上げるときの動きは、まずわずかに長くストレッチし、次に少し速く再生して元の長さに戻す、と考えると関係がつかめます。

## 大きな変更でアーティファクトが出る理由

どちらの操作も、情報を生成または破棄します。

| 編集 | 起こりやすい問題 |
|------|------------------|
| 音を 2 倍の長さに伸ばす | 追加された音の多くが位相の仮定から合成される |
| 声を完全 5 度上げる | 補正しない限りフォルマントも動く |
| 大きくトランジェントを変える | アタックが軟らかくなったり、にじんだりする |

小さな変更では仮定が成り立つので透明に済みます。大きな変更では仮定が崩れ、にじみ、トランジェント（音の出はじめやドラムの打点の鋭い立ち上がり）の鈍り、「チップマンク」的な音色として表に出ます。

実用上の指針は、自然な結果を求めるなら控えめに、大きな変更は意図した音作りの効果として扱う、ということです。

::: details libsonare がストレッチをどう実装するか
libsonare の `timeStretch` と `pitchShift` は、*ピークロック付き*フェーズボコーダのコア（`phase_vocoder_phaselocked`、`NativeSpectral` バックエンド）に、ピッチ軸のリサンプリングを組み合わせたものです。ピークロックはスペクトルのピーク周辺のビンの位相を揃えて保つ仕組みで、上で触れた「位相っぽい」アーティファクトが目立ちにくいのはこれが効いているためです。ロックなしの素の `phase_vocoder` は C++ 側だけの軽量フォールバックとして残っており、JavaScript と Python の入口は常にピークロック付きの経路を通り、バックエンドの選択肢を公開していません。

- `timeStretch` は、フェーズボコーダで時間軸を伸縮します。
- `pitchShift` は、ピッチ比でタイムストレッチした後、元の長さへリサンプルします。
- 同じコアは `noteStretch`（区間限定のストレッチ）や `voiceChange` のピッチ経路でも使われます。

入力は、デコード済みのモノラル `Float32Array` またはサンプル列です。品質は変更量に応じてなだらかに劣化するため、控えめな比率ならたいていの素材でアーティファクトを聞き取れないレベルに抑えられます。ただしゼロにはなりません。どの呼び出しも窓長 2048 サンプルの STFT を往復し、位相を再伝播させるため、比率が 1 に近くてもトランジェントのわずかな鈍りと位相感は残ります。ビット単位で元のまま残したい箇所は、そもそもストレッチャーに通さないでください。
:::
