# バスとセンド

ミキサーはストリップの集まりだけではありません。それらを合算しグループ化する**ルーティンググラフ**です。

**バス**は共有の行き先です。**センド**はそこへ信号を送るタップです。

この 2 つを正しく扱えば、多数のストリップをまとめて制御できるミックスになります。このページでは、ルーティングモデルを libsonare の `Bus` とセンドプロセッサに沿って説明します。入門的な説明は [ミキシングの基礎](../concepts/mixing-basics.md) を参照してください。

## バス: master・aux・submix

**バス**は複数の信号を合算する行き先です。libsonare はバスに**ロール**を与えます。

- **master** — すべての信号が最後に到達するステレオ出力。
- **aux** — センドのリターン。共有エフェクト（1 つのリバーブ、1 つのディレイ）はここに置きます。
- **submix** — 関連トラック（ドラムすべて）をまとめ、1 つとして処理・調整できるグループ。

ドラムの submix に挿したコンプはキットをまとめ、1 本のフェーダーでキット全体を制御します。master が特別なのは、グラフの最後のバスである点だけです。

## センド: 並列のコピー

**インサート**はトラックを*直列*に処理し、トラック全体がそこを通ります。**センド**は違います。トラックの*コピー*を*並列*にバスへ送ります。複数のトラックで共有するエフェクトに使い、ボーカル、スネア、ギターがそれぞれ自前のリバーブを持たずに、1 つのリバーブ空間に収まるようにします。

## プリフェーダーとポストフェーダー

センドはフェーダーの**前**からでも**後**からでも信号を取れます。ここが、ルーティングで最も間違えやすい判断です。

| タップ | フェーダーに追従？ | 用途 |
|--------|--------------------|------|
| プリフェーダー | しない | ヘッドホン／キューミックス、フェーダーを動かしても一定に保ちたいエフェクト |
| ポストフェーダー | する | バランスに比例させたいリバーブ／ディレイ |

## VCA グループと submix

**submix** は音声の経路を変えます。グループ化したトラックは実際に submix バスを流れます。**VCA グループ**は経路を変えません。VCA（voltage-controlled amplifier）は名前の由来になったコンソールの回路で、ここでは音声の行き先を変えずに、複数トラックのレベルを 1 本のフェーダーでまとめて動かす仕組みを指します。パートを別々のバスへ流したまま、合計レベルだけを 1 か所で握りたいときに使います。

::: details libsonare がルーティングをどうモデル化するか
| 要素 | 役割 |
|------|------|
| `Bus` | `BusRole`（`Master`/`Aux`/`Subgroup`）を持ち、`BusProcessor` を実行 |
| `FxBus` | 共有エフェクトをホスト |
| `SendProcessor` | `SendTiming`（プリ／ポストフェーダー）で選んだ `TapPoint` から行き先バスへ送る |
| `VcaGroup` | 音声を再ルーティングせずに、メンバーストリップへ共有ゲインオフセットを適用 |

`submix` というロール値は存在しません。シーンレベルの `role` は自由文字列で、特別に解釈されるのは `master` だけです。`submix`・`subgroup`・`group` などはいずれも同じ「master ではない一般のバス」としてコンパイルされます（組み込みのドラムバスプリセットは `"subgroup"` を書き出します）。

ストリップ・バス・センド・接続からなるグラフ全体は、保存可能なシーンで記述されます。プラグインディレイ補償（PDC）付きで動くため、並列経路の時間整合も保たれます。フィールド単位の形式は [ミキシングシーン JSON](../../mixing-scene-json.md) を参照してください。
:::
