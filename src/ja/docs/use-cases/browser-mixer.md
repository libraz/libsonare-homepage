# ブラウザでミキシングアプリを作る

ミキシング専用の Web アプリには、ファイル読み込み、同期再生、トラック操作、ミックスの書き出しが必要です。libsonare が DSP とルーティングを提供し、アプリが画面、音源の保存、WAV への変換を担当します。MIDI 編集、音源、録音を組み込む必要はありません。

[ミキシングスタジオ](/ja/mixing)は、その実装例です。ローカルのステムを読み込み、フェーダー、パン、音色 EQ、共有リバーブへのセンドを調整して、ステレオ WAV を書き出せます。**デモを読み込み**から始め、**再生**してフェーダーを動かし、**ミックスをバウンス**して **WAV を保存**します。音声処理はブラウザ内で完結します。

## 再生とレンダリングの API を選ぶ

| アプリの動作 | 入口 | アプリ側の担当 |
|---|---|---|
| ステレオ配列を一括でミックス | [`mixStereo`](../mixing.md#一括ミックス-mixstereo) | デコード、入力の位置合わせとパディング、結果のファイル化 |
| 独自の再生処理でステムミキサーを動かす | [`Mixer`](../mixing.md#シーンベースのミックス-mixer) | ブロック供給、再生位置の管理、UI 操作の伝達、同じグラフのオフライン処理 |
| タイムライン再生、操作、オートメーション、書き出しをまとめて扱う | `@libraz/libsonare/worklet` の [`SonareEngine`](../realtime-streaming.md#audioworklet-での使い分け) | クリップ読み込み、レーンとルーティングの設定、出力接続、UI と保存 |

新しく試聴と書き出しを備えたアプリを作る場合は、既存の [SonareEngine の設定例と操作一覧](../realtime-streaming.md#レンダー領域でマスタリングをプレビューする)から始めてください。この API は操作を AudioWorklet 内のエンジンとオフライン用エンジンに反映します。`renderOffline` が返すのは PCM なので、WAV への変換とダウンロードはアプリが担当します。長いオフライン処理には Worker の設計も必要です。メソッドが async でも、計算が自動でメインスレッドの外へ移るわけではありません。

ミキシングスタジオは表の 2 行目の構成です。独自の小さな再生処理でデータの流れを確認できますが、再生中に操作するとミキサーシーン全体を再構築します。その際、リバーブの残響など、プロセッサの内部状態がリセットされます。頻繁に操作するアプリではプロセッサを保持し、個別の setter で値を変更してください。

## 音源、ミキサーシーン、プロジェクト設定を分ける

1. すべてのファイルを 1 つの `AudioContext` でデコードします。デモの `decodeAudioFile` は、そのコンテキストのサンプルレートで左右のチャンネルを保持します。モノラル入力は左右へ複製します。3 チャンネル以上の入力は先頭 2 チャンネルだけを使うため、サラウンド対応では明示的なチャンネル割り当てが必要です。
2. PCM 配列とクリップの開始位置を、アプリのトラック状態に保存します。読み込んだステムはすべて 0 秒から始まり、移動は明示的なタイムライン操作で行います。左右のチャンネルを保持してください。解析用のモノラル配列ではステレオ再生を再現できません。
3. 操作値から[ミキサーシーン](../mixing-scene-json.md)を作ります。シーンはストリップ、バス、インサート、センド、接続を記述し、音源やクリップの配置は含みません。
4. [デモのプロジェクト設定](../mixing-demo-project-json.md)を別に保存します。トラック名、開始位置、オートメーション、操作値を保持します。音源は含まないので、設定を読み込む前に対応する音声ファイルを開き直します。
5. PCM をレンダリングし、WAV に変換してダウンロードします。デモの `wavBlob` は PCM16 を書き出し、表現範囲を超えたサンプルをクリップします。バウンス後にピークと True Peak を確認してください。レベルを下げる場合は操作値を調整し、再度バウンスしてからダウンロードします。

セッション全体を開き直せるアプリには、保存した音声ファイルと安定した音源 ID など、アプリ独自の音源保存が必要です。ミキサーシーン JSON とデモの設定ファイルは、どちらも音源を含むプロジェクトアーカイブではありません。

## 試聴で確認できる範囲

| 動作 | ミキシングスタジオ |
|---|---|
| トラック操作、音色 EQ、リバーブ、VCA | 独自 WASM ミキサーによる試聴が利用できる場合に反映 |
| フェーダー、パン、幅のオートメーション | バウンス時に適用。再生は現在の固定値を使用 |
| トラックとマスターのメーター表示 | 直近のバウンス結果を表示。連続したライブ計測ではない |
| 試聴の代替処理 | ブラウザのノードでトリム、音量、パンを処理。DSP 全体を使わないため警告を表示 |
| 残響とグラフのレイテンシ | 素材が終わった後も、試聴とバウンスを延長 |
| プロジェクト設定の読み書き | 読み込み済みの一致するトラックへ設定を復元。音源は含まない |

Worker にはバウンス要求用に複製した PCM を転送するため、UI が保持する元の配列は引き続き使えます。素材のタイムライン長に、グラフが報告する残響とレイテンシを加えてレンダリングします。デコード済み入力、Worker 用の複製、パディング済みチャンネル、出力配列を保持するため、処理中のメモリ使用量が増えます。

8 トラックと 5 分の制限はデモ側の上限で、エンジンの上限ではありません。引き上げる場合は対象端末でメモリと音声スレッドの負荷を計測してください。長いセッションでは[クリップ音声のページストリーミング](../realtime-streaming.md#クリップ音声のページストリーミング)を参照してください。リアルタイム OPFS 処理には SharedArrayBuffer とクロスオリジン分離が必要ですが、デモ独自の再生処理はそれらを使わずに動きます。

## ミックスに使う前に確認する

- 同じセッションから書き出したステムを読み込み、開始位置が揃っていることを確認します。
- 同じ操作値で固定設定の試聴とバウンスを比較します。このデモではオートメーションをバウンスで別途確認します。
- モノラルとステレオ、異なるファイルサンプルレート、ミュートとソロ、クリップの開始位置、末尾のリバーブ残響を確認します。
- 設定を書き出し、対応する音源を開き直して設定を読み込みます。音源を保持したまま操作値が復元されることを確認します。
- 読み込み中やバウンス中に再生を停止し、画面を閉じます。ネイティブミキサーのハンドル、Worker、AudioContext、ダウンロード URL を解放します。
